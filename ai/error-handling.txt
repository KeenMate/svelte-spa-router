GLOBAL ERROR HANDLING
=====================

SETUP
-----
// main.js
import { mount } from 'svelte'
import { configureGlobalErrorHandler } from '@keenmate/svelte-spa-router/helpers/error-handler'
import GlobalErrorHandler from '@keenmate/svelte-spa-router/helpers/GlobalErrorHandler.svelte'
import App from './App.svelte'

configureGlobalErrorHandler({
    strategy: 'navigateSafe',
    safeRoute: '/',
    maxRestarts: 3,
    restartWindow: 60000,           // 1 minute
    isDevelopment: import.meta.env.DEV,
    onError: (error, errorInfo, context) => {
        // Wire up your own notification UI here (toast, snackbar, etc.)
        toast.error(`Something went wrong: ${error.message}`)
        // Log to Sentry, LogRocket, etc.
        Sentry.captureException(error, { extra: errorInfo })
    }
})

mount(GlobalErrorHandler, {
    target: document.getElementById('app'),
    props: { component: App }
})

STRATEGIES
----------
navigateSafe (default):
- Navigate to safeRoute on error
- Safe recovery without reload
- Best for most apps

restart:
- Full page reload
- Clears all state
- Use for unrecoverable errors

showError:
- Display error component
- User can choose action
- Good for development

custom:
- Your own recovery function (onRecover)
- Full control

CONFIGURATION OPTIONS
---------------------
strategy:           'navigateSafe' | 'restart' | 'showError' | 'custom'
safeRoute:          string (default: '/')
maxRestarts:        number (default: 3)
restartWindow:      number ms (default: 60000)
autoRestart:        boolean (default: false)
restartDelay:       number ms (default: 5000)
showErrorComponent: boolean (default: false)
ignoreErrors:       Array of RegExp | string patterns to ignore
isDevelopment:      boolean — shows stack traces in ErrorDisplay
onError:            (error, errorInfo, context) => void
onRecover:          (error, errorInfo, context, helpers) => void

RESTART LOOP PREVENTION
-----------------------
Tracks restart count in sessionStorage:
- Restart count incremented on each restart
- Cleared on successful navigation
- Max 3 restarts by default within restartWindow
- After max reached, falls back to showError

import { canRestart, getRestartCount } from '@keenmate/svelte-spa-router/helpers/error-handler'

if (canRestart()) {
    await restart()
} else {
    console.error('Max restarts reached — surfacing error UI instead')
}

HELPER FUNCTIONS
----------------
import {
    restart,
    navigate,
    showError,
    canRestart,
    getRestartCount
} from '@keenmate/svelte-spa-router/helpers/error-handler'

restart(): void
- Full page reload, increments restart count

navigate(route: string): Promise<void>
- Navigate via push() — safe SPA navigation

showError(): void
- Force the error component to render (without changing the strategy)

canRestart(): boolean
- True if restart count is below maxRestarts within restartWindow

getRestartCount(): number
- Current restart count

ERROR FILTERING (ignoreErrors)
-------------------------------
Skip handling for known non-critical errors:

configureGlobalErrorHandler({
    strategy: 'navigateSafe',
    ignoreErrors: [
        /ResizeObserver loop limit exceeded/,
        'ChunkLoadError',           // string match (case-sensitive includes)
        /network.*timeout/i
    ]
})

Matched errors bypass the handler entirely — browser default behavior
applies (typically: log to console and move on).

ONERROR CALLBACK
----------------
Called for EVERY caught error, before any recovery strategy runs. Use it
for observability (Sentry, LogRocket, analytics) and notification UI
(toast, snackbar) — the router intentionally does not render its own toast.

configureGlobalErrorHandler({
    onError: (error, errorInfo, context) => {
        // error      — the thrown Error object
        // errorInfo  — { message, stack, route, timestamp, ... }
        // context    — current router context

        // Telemetry
        Sentry.captureException(error, { extra: errorInfo })

        // Notification — use YOUR app's toast library
        toast.error(error.message)

        // Analytics
        gtag('event', 'exception', {
            description: error.message,
            fatal: false
        })
    }
})

CUSTOM RECOVERY (onRecover)
---------------------------
For strategy: 'custom', implement your own recovery flow with full access
to the helper functions:

configureGlobalErrorHandler({
    strategy: 'custom',
    onRecover: (error, errorInfo, context, helpers) => {
        const { restart, navigate, showError, canRestart } = helpers

        if (error.name === 'ChunkLoadError') {
            // New deployment — reload to pull fresh assets
            if (canRestart()) restart()
            else showError()
        } else if (error.message.includes('auth')) {
            navigate('/login')
        } else if (error.message.includes('network')) {
            // Notify and stay put — your onError already toasted
            return
        } else {
            navigate('/')
        }
    }
})

NOTE: The built-in error toast was removed in v5.2.0-rc02. Earlier versions
had a `showToast` config flag and rendered a `.error-toast` element from
inside GlobalErrorHandler. Notification UI is now the consumer's
responsibility — wire it up inside onError. If you have old code passing
`showToast: true`, remove it (TypeScript will flag it).

COMPONENT USAGE
---------------
// main.js
import { mount } from 'svelte'
import GlobalErrorHandler from '@keenmate/svelte-spa-router/helpers/GlobalErrorHandler.svelte'
import App from './App.svelte'

mount(GlobalErrorHandler, {
    target: document.getElementById('app'),
    props: {
        component: App  // Your root component
    }
})

GlobalErrorHandler catches:
- Render errors
- $effect errors
- Event handler errors
- Unhandled promise rejections
- Async errors that bubble up

DEFAULT ERROR UI
----------------
Uses ErrorDisplay.svelte:
- Full-page error display
- Shows error message
- Stack trace (when isDevelopment: true)
- Actions: Go Home, Reload, Continue
- Warning when multiple errors detected in session

CUSTOM ERROR COMPONENT
----------------------
Pass your own component for branded error UI:

// CustomError.svelte
<script>
let { error = null, onContinue = () => {}, onReload = () => {}, onGoHome = () => {} } = $props()
</script>

<div class="error">
    <h1>Oops! {error?.message}</h1>
    <button onclick={onContinue}>Continue</button>
    <button onclick={onReload}>Reload</button>
    <button onclick={onGoHome}>Go Home</button>
</div>

// main.js
mount(GlobalErrorHandler, {
    target: document.getElementById('app'),
    props: {
        component: App,
        errorComponent: CustomError
    }
})

ERROR COMPONENT PROPS
---------------------
{
    error: Error,
    errorInfo: { message, stack, route, timestamp, ... },
    onContinue: () => void,    // clears error and stays on route
    onReload: () => void,      // full page reload
    onGoHome: () => void       // navigates to safeRoute
}

DEVELOPMENT VS PRODUCTION
--------------------------
Different strategies per environment:

if (import.meta.env.DEV) {
    configureGlobalErrorHandler({
        strategy: 'showError',
        isDevelopment: true       // show stack traces
    })
} else {
    configureGlobalErrorHandler({
        strategy: 'navigateSafe',
        safeRoute: '/',
        onError: (err, info) => Sentry.captureException(err, { extra: info })
    })
}

COMBINING WITH ROUTE CONDITIONS
--------------------------------
Throwing inside a condition is caught by GlobalErrorHandler:

import { wrap } from '@keenmate/svelte-spa-router/wrap'

const routes = {
    '/protected': wrap({
        asyncComponent: () => import('./Protected.svelte'),
        conditions: [
            async (detail) => {
                const valid = await checkAuth()
                if (!valid) {
                    throw new Error('Unauthorized access')
                }
                return true
            }
        ]
    })
}

For "expected" failure paths (auth, permission denied), prefer returning
false from the condition + onConditionsFailed event over throwing — the
error handler is for unexpected exceptions.

TESTING ERROR HANDLING
----------------------

    throw new Error('Async error')
}

PERFORMANCE
-----------
- No overhead when no errors
- Single window event listener
- SessionStorage for restart tracking
- Minimal DOM changes

BEST PRACTICES
--------------
- Configure before app mount
- Wire onError to your telemetry AND notification UI
- Use navigateSafe for most cases
- Set appropriate maxRestarts / restartWindow
- Filter known non-critical errors via ignoreErrors
- Use showError + isDevelopment in development for stack traces
- Provide custom errorComponent for branding

DEBUGGING
---------
Enable error handler logging:

import { setCategoryLevel } from '@keenmate/svelte-spa-router/logger'

setCategoryLevel('ROUTER:ERROR_HANDLER', 'debug')

Logs show:
- Error captured
- Strategy selected
- Recovery executed
- Restart count

LIMITATIONS
-----------
- Only catches unhandled errors
- Won't catch syntax errors during initial load
- Requires GlobalErrorHandler component as root
- SessionStorage required for restart tracking
