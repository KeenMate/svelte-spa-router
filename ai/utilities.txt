UTILITIES
=========

SEE ALSO: querystring-filters.txt for the modern reactive querystring/
filter API (configureQuerystring + query() + updateQuerystring, and
configureFilters + filters() + updateFilters). This file covers the
stateless utility functions and low-level helpers.

URL HELPERS
-----------
import { joinPaths } from '@keenmate/svelte-spa-router/helpers/url-helpers'

joinPaths(basePath, ...paths)

Intelligent path joining with slash normalization:

joinPaths('/app', 'users', '123')
// Result: '/app/users/123'

joinPaths('/app/', '/users/', '/123/')
// Result: '/app/users/123'

joinPaths('', 'users', '123')
// Result: '/users/123'

joinPaths('/app', '')
// Result: '/app'

Rules:
- Removes duplicate slashes
- Ensures leading slash
- Removes trailing slash
- Handles empty strings

QUERYSTRING PARSING (STATELESS)
--------------------------------
import { parseQuerystring } from '@keenmate/svelte-spa-router/helpers/querystring-helpers'

parseQuerystring(queryString, options?)

Parse query string to object:

parseQuerystring('tab=settings&page=2')
// Result: { tab: 'settings', page: '2' }

parseQuerystring('?tab=settings&page=2')
// Result: { tab: 'settings', page: '2' } (leading ? stripped)

parseQuerystring('')
// Result: {}

parseQuerystring('search=hello%20world')
// Result: { search: 'hello world' } (URL decoded)

parseQuerystring('tags=foo,bar,baz', { arrayFormat: 'auto' })
// Result: { tags: ['foo', 'bar', 'baz'] }

parseQuerystring('tags=foo&tags=bar', { arrayFormat: 'repeat' })
// Result: { tags: ['foo', 'bar'] }

QUERYSTRING BUILDING (STATELESS)
---------------------------------
import { stringifyQuerystring } from '@keenmate/svelte-spa-router/helpers/querystring-helpers'

stringifyQuerystring(object, options?)

Build query string from object:

stringifyQuerystring({ tab: 'settings', page: 2 })
// Result: 'tab=settings&page=2'

stringifyQuerystring({ search: 'hello world' })
// Result: 'search=hello%20world' (URL encoded)

stringifyQuerystring({})
// Result: ''

stringifyQuerystring({ foo: null, bar: undefined })
// Result: '' (null/undefined omitted by default)

stringifyQuerystring({ ids: [1, 2, 3] })
// Result: 'ids=1&ids=2&ids=3' (default: repeat format)

stringifyQuerystring({ ids: [1, 2, 3] }, { arrayFormat: 'comma' })
// Result: 'ids=1,2,3'

ACCESSING CURRENT QUERYSTRING
------------------------------
Raw string:
import { querystring } from '@keenmate/svelte-spa-router'

const qs = $derived(querystring())   // 'tab=settings&page=2'

Parsed object (stateless):
import { parseQuerystring } from '@keenmate/svelte-spa-router/helpers/querystring-helpers'

const params = $derived(parseQuerystring(qs))

Parsed reactive (configured, recommended):
import { query } from '@keenmate/svelte-spa-router/helpers/querystring'

const q = $derived(query())   // already parsed + array-format aware
// See querystring-filters.txt for the full reactive API.

NAVIGATION WITH QUERYSTRING
----------------------------
Use push()/replace() with a query object — the router serializes it:

await push('/search', {}, { q: 'svelte', page: 2 })
// URL: /search?q=svelte&page=2

await push('userProfile', { userId: 123 }, { tab: 'settings' })
// URL: /user/123?tab=settings

QUERYSTRING IN LINK ACTION
---------------------------
import { link } from '@keenmate/svelte-spa-router'

<a href="/search?q=svelte&page=2" use:link>Search</a>

// With named-route binding:
<a use:link={['search', {}, { q: 'svelte', page: 2 }]}>Search</a>

UPDATING QUERYSTRING (MERGE WITH CURRENT URL)
----------------------------------------------
import { updateQuerystring } from '@keenmate/svelte-spa-router/helpers/querystring-helpers'

// Merge new params with current (default behavior)
await updateQuerystring({ page: 3 })

// Remove a parameter
await updateQuerystring({ category: undefined })

// Replace entire querystring (don't merge)
await updateQuerystring({ q: 'new' }, { merge: false })

CLEARING QUERYSTRING
--------------------
Navigate to the same path with empty query:

await push(location(), {}, {})

QUERYSTRING IN REFERRER
-----------------------
import { navigationContext } from '@keenmate/svelte-spa-router'

const navContext = $derived(navigationContext())
const referrer = $derived(navContext?.referrer)
const previousQuery = $derived(referrer?.querystring)

if (previousQuery) {
    const params = parseQuerystring(previousQuery)
    // Use previous params (e.g., return to filtered list)
}

const fullUrl = $derived(`${path}?${query}`)

MANUAL URL PARSING
------------------
For complex parsing, use URL API:

const url = new URL(window.location.href)
const path = url.pathname
const query = url.search.slice(1)
const params = parseQuerystring(query)

ARRAY QUERY PARAMS
------------------
parseQuerystring('ids=1&ids=2&ids=3', { arrayFormat: 'auto' })
// Result: { ids: ['1', '2', '3'] }

stringifyQuerystring({ ids: [1, 2, 3] }, { arrayFormat: 'repeat' })
// Result: 'ids=1&ids=2&ids=3'

stringifyQuerystring({ ids: [1, 2, 3] }, { arrayFormat: 'comma' })
// Result: 'ids=1,2,3'

NESTED OBJECTS (NOT SUPPORTED)
-------------------------------
Querystring helpers handle flat key/value pairs only:

stringifyQuerystring({ user: { id: 123, name: 'Alice' } })
// Result: 'user=%5Bobject+Object%5D' — NOT what you want

Flatten objects before stringifying:

stringifyQuerystring({
    'user.id': 123,
    'user.name': 'Alice'
})
// Result: 'user.id=123&user.name=Alice'

URL ENCODING
------------
Both parse and stringify handle URL encoding automatically:

stringifyQuerystring({ search: 'hello world' })
// Result: 'search=hello%20world'

parseQuerystring('search=hello%20world')
// Result: { search: 'hello world' }

BOOLEAN PARAMS
--------------
Booleans are stringified to strings, parsed as strings:

stringifyQuerystring({ active: true })
// Result: 'active=true'

parseQuerystring('active=true')
// Result: { active: 'true' }  ← STRING, not boolean

// Convert manually:
const active = params.active === 'true'

NUMERIC PARAMS
--------------
Numbers are stringified to strings, parsed as strings:

stringifyQuerystring({ page: 2 })
// Result: 'page=2'

parseQuerystring('page=2')
// Result: { page: '2' }  ← STRING, not number

// Convert manually:
const page = parseInt(params.page, 10)

NULL/UNDEFINED HANDLING
-----------------------
By default, null and undefined are dropped:

stringifyQuerystring({ foo: null, bar: undefined, baz: '' })
// Result: 'baz=' (empty string preserved)

REACTIVE QUERYSTRING (LIVE UPDATES)
------------------------------------
import { querystring } from '@keenmate/svelte-spa-router'
import { parseQuerystring } from '@keenmate/svelte-spa-router/helpers/querystring-helpers'

const params = $derived(parseQuerystring(querystring()))
const page = $derived(parseInt(params.page || '1', 10))
const search = $derived(params.search || '')

(Or use the configured reactive accessor — see querystring-filters.txt.)

SEARCH PARAMS API ALTERNATIVE
------------------------------
You can use the browser's URLSearchParams directly:

const params = new URLSearchParams(querystring())
const search = params.get('search')
params.set('page', '2')

But the helpers handle SPA-mode quirks (hash prefix, base path) and
array/null behavior consistently, so prefer them for in-app code.

HASH FRAGMENTS
--------------
In hash routing mode, the URL hash IS the path. To use additional hash
fragments for scrolling, append after the path:

http://example.com/#/page#section
// path = /page, hash fragment = #section

window.location.hash    // Includes everything
document.getElementById(fragmentId)?.scrollIntoView()

In history mode, regular hash fragments work as expected.

COMMON PATTERNS
---------------
Pagination:
import { querystring, push } from '@keenmate/svelte-spa-router'
import { parseQuerystring } from '@keenmate/svelte-spa-router/helpers/querystring-helpers'

const params = $derived(parseQuerystring(querystring()))
const page = $derived(parseInt(params.page || '1', 10))

function nextPage() {
    push(location(), {}, { ...params, page: page + 1 })
}

Tab navigation:
const tab = $derived(params.tab || 'overview')

function switchTab(newTab) {
    push(location(), {}, { ...params, tab: newTab })
}

(For both of the above, prefer updateQuerystring({ ... }) — it auto-
merges and handles encoding.)

BEST PRACTICES
--------------
- Use parseQuerystring/stringifyQuerystring (not the browser's URLSearchParams)
  for SPA-aware behavior
- For reactive UIs, prefer the configured query() accessor (see
  querystring-filters.txt) — it tracks array formats and stays in sync
- Convert string params to numbers/booleans explicitly
- Don't store sensitive data in querystrings — use navigationContext for that
- For nested data, flatten with dot notation or use navigationContext
